# chatatui — plan

Minimal ChatGPT/Claude-like chat client for local LLMs, in the terminal.
OpenAI-compatible API (`POST /v1/chat/completions`, `stream: true`, SSE), default
`http://localhost:11434/v1` (Ollama); also works with llama.cpp server, LM Studio, vLLM.

## Architecture

```
Event (key, tick, LLM, DB)
  → keymap → Action
  → App::update(Action) -> Vec<Command>   // pure: no I/O
  → Runtime executes commands             // spawns tokio tasks, storage calls
  → results come back as AppEvent through the template's mpsc channel
ui::render(&App, frame)                   // read-only
```

- Derived render data (`transcript.rs`: per-message line cache) is refreshed in `update`,
  never during rendering. Tokens only invalidate the streamed message; the next `Tick`
  (30 fps) re-renders it, so markdown work is capped at the tick rate and only the last
  message is recomputed. `layout.rs` is shared by update and render so they agree on
  sizes. Closed code blocks are highlighted once (cache in `markdown/highlight.rs`).
- Streaming runs in its own tokio task: ContextProvider → prompt → HTTP stream →
  `AppEvent::Llm { request_id, LlmEvent::{Token, Done, Error} }`. Cancellation via
  `CancellationToken`; `request_id` discards stale events.
- `LlmClient` (impl `OpenAiCompatibleClient`, mocked in tests) and `ContextProvider`
  (impl `NoContext`) are async traits behind `Arc<dyn …>`. RAG plugs into `ContextProvider`
  later; `prompt.rs` injects its chunks as an extra system message.
- Lib + thin bin (`src/lib.rs` / `src/main.rs`), derived from the ratatui
  `event-driven-async` template (`event.rs` kept, loop moved to `runtime.rs`).

## Decisions

- `ratatui-textarea` 0.9 (maintained fork, ratatui 0.30) instead of `tui-textarea` 0.7
  (stuck on ratatui 0.29).
- Kitty keyboard protocol enabled when supported, so `Shift+Enter` / `Ctrl+M` work.
  Fallbacks: `Alt+Enter` or `Ctrl+J` for a new line, `F2` for the model picker.
- Bracketed paste enabled: pasted newlines never submit.
- Mouse capture on by default for wheel scrolling (`mouse_capture = false` in the config
  restores native selection; otherwise Shift+drag selects).
- Scrolling: PgUp/PgDn, Ctrl+Home/Ctrl+End, mouse wheel, and Up/Down when the input is
  empty. Markdown tables are rendered too (simple aligned columns).
- History: SQLite (`rusqlite`, bundled) in the platform data dir
  (`~/.local/share/chatatui/chatatui.db`), WAL mode, schema versioned with
  `PRAGMA user_version`. A dedicated storage thread executes requests in order; the app
  only emits `Command::Store(...)` and receives `StoreEvent`s.
- Writes are idempotent upserts: the user message is saved when sent, the reply when it
  ends (complete / cancelled / failed). Quitting mid-reply saves the partial reply (the
  runtime waits for the storage thread before exiting).
- Conversation ids are generated by the app (session seed from time + pid, plus a
  counter), so no round-trip to the database is needed. A conversation is only stored once
  it has a message. Message ids are per conversation, hence the transcript cache is
  cleared when switching conversations.
- Model picked at runtime (Ctrl+M / F2, list from `GET /models`, type to filter) applies to
  the next request and is recorded on the current conversation (`StoreRequest::SetModel`,
  without changing its position in the list). Reopening a conversation restores its model.
  The config file is never rewritten (keeps user comments).
- Commands: one registry (`commands.rs`) feeds slash commands, the palette and the help
  screen. Slash commands only apply to single-line input; `//text` sends `/text`. Typing
  `/` shows suggestions (↑↓, Tab completes, Enter runs the highlighted one, Esc hides them).
  Commands work while a reply streams. Side effects are called `Effect` (not `Command`) to
  avoid confusion with user commands.
- Providers: `[providers.*]` sections over three presets (ollama, openai, claude). Keys come
  from environment variables (or the file) and never reach `App`; the runtime builds one
  client per provider, and a provider without its key gets an `Unavailable` client that
  explains why. Claude uses the native Messages API (Anthropic's OpenAI compatibility
  layer is not meant for production). Each conversation stores its provider (schema v2).
  Only one provider answers a given request; switching mid-conversation sends the whole
  history to the new one.
- Context: `LlmEvent::Usage` carries server counts; `App::context_usage()` = last measure
  + estimate of newer messages (else a full estimate), flagged measured/estimated.
  `LlmClient::context_window()` probes native endpoints (Ollama `/api/ps`, LM Studio
  `/api/v1/models`, llama.cpp `/props`, Anthropic `/v1/models/{id}`); config
  `context_window` wins. `/context` and `/prompt` are text popups built from the same
  `prompt::build_messages` as the real request.
- Acting on the context: `Role::Attachment` (file text + `source`) and `Role::Summary`
  messages, and a per-conversation `context_start` (schema v3). Messages before it stay on
  screen, greyed out under a separator, but are not sent. `/clear` moves it past the last
  message; `/compact` streams a summary (a `JobKind::Summary` job, same machinery as a
  reply) and moves it to the summary once complete — a cancelled or failed summary
  changes nothing. Attachments are sent as numbered context chunks in the system
  message, exactly like future RAG chunks. File reading and path completion run on
  blocking tasks (`files.rs`).
- Popups (model picker, palette, help) are one `Overlay` at a time and take the focus.
- Esc closes the topmost overlay first: model popup, then conversation list, then cancels
  the generation, then stops indexing.
- UI strings in French, code and comments in English. No `unwrap()` outside tests.
